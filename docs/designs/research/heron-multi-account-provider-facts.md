# Provider facts for heron-multi-account

Checked against the official Google and Microsoft pages on 2026-11-22. Each line paraphrases the page. **UNVERIFIED** means no official page said it, so the design must not rely on it.

## Google

| id | Fact | Verdict | Source |
|---|---|---|---|
| G1 | An External app in **Testing** gets refresh tokens that expire after 7 days, unless it asks only for name, email and profile. Test users' authorizations themselves expire seven days after consent. | Confirmed | https://developers.google.com/identity/protocols/oauth2 ; https://support.google.com/cloud/answer/15549945 |
| G2 | In Testing, only listed test users can sign in. The list holds at most 100 users. They are managed on the "Audience" page of the Google Auth Platform (`console.developers.google.com/auth/audience`). | Confirmed. The exact "Test users > Add users" button wording is not on the page | https://support.google.com/cloud/answer/15549945 |
| G3 | An app for fewer than 100 known users may be set to **In production** without verification. Users then click through an "unverified app" warning. The cap is 100 new users over the app's lifetime and can't be reset. "Personal" mode is limited to the creator's own account, so it doesn't fit several accounts. | Confirmed | https://support.google.com/cloud/answer/13464323 ; https://support.google.com/cloud/answer/7454865 |
| G3a | In production, refresh tokens no longer expire after 7 days. | **UNVERIFIED**: only implied, because the 7-day rule is stated for Testing | (production-readiness page returned 404) |
| G4 | A Workspace admin block shows the error `admin_policy_enforced`. By default, users may use any third-party app. Admins can block unconfigured apps or restrict high-risk scopes; `gmail.readonly` is on that list. An admin allows one client under Security > Access and data control > API controls > Manage App Access ("Configure new app", search by client ID, choose Trusted). | Confirmed. The "Access blocked" wording is UNVERIFIED | https://developers.google.com/identity/protocols/oauth2 ; https://knowledge.workspace.google.com/admin/apps/control-which-third-party-and-internal-apps-access-google-workspace-data |
| G5 | Google may show `admin_policy_enforced`, `org_internal` and similar errors on its own page instead of finishing the flow. `access_denied` on the redirect is documented only for a user who declines. | Partly. Whether a non-test-user or admin block ever reaches the redirect URI is **UNVERIFIED** | https://developers.google.com/identity/protocols/oauth2/native-app |
| G6 | `prompt` is a space-separated list. `select_account consent` is allowed; `none` can't be combined. | Confirmed | https://developers.google.com/identity/protocols/oauth2/web-server |

## Microsoft

| id | Fact | Verdict | Source |
|---|---|---|---|
| M1 | The `/common` authority needs the supported account types "Accounts in any organizational directory and personal Microsoft accounts" (`AzureADandPersonalMicrosoftAccount`). A single-tenant app on `/common` fails with AADSTS50194 and must use its tenant's authority. | Confirmed | https://learn.microsoft.com/en-us/entra/identity-platform/msal-client-application-configuration ; https://learn.microsoft.com/en-us/entra/identity-platform/supported-accounts-validation ; https://learn.microsoft.com/en-us/entra/identity-platform/reference-error-codes |
| M2 | `sub` is pairwise: it is unique per application ID and depends on the tenant, so a new client ID gives the same person a new `sub`. `oid` + `tid` is the identifier that is the same across apps, and `oid` needs the `profile` scope. Personal accounts have `tid` `9188040d-6c67-4c5b-b112-36a304b66dad`. | Confirmed | https://learn.microsoft.com/en-us/entra/identity-platform/id-token-claims-reference |
| M3 | Codes: 65001 (no consent yet), 65004 (user declined), 90093 (policy blocks consent), 90094 (admin consent required), 900941 (risky app needs admin consent), 50020 (account not in tenant), 50194 (single-tenant on /common), 700016 (app not in directory), 50105 (user not assigned). Microsoft warns that code numbers and text change, so apps should not drive logic from them. | Confirmed | https://learn.microsoft.com/en-us/entra/identity-platform/reference-error-codes |
| M4 | Where user consent is blocked, non-admins are told to ask an admin. Error responses *may* be sent to the redirect URI. Pressing "return to app" after an admin-consent request sends AADSTS65004 to the redirect URI. By default, users can consent to permissions that don't need an admin. Publisher verification needs a Microsoft AI Cloud Partner Program ID, and **apps registered with a personal Microsoft account can't be verified**. With risk-based step-up consent, users can't consent to most new unverified multitenant apps. | Partly. Whether the blocked-consent screen itself redirects is **UNVERIFIED** | https://learn.microsoft.com/en-us/entra/identity-platform/application-consent-experience ; https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/configure-user-consent ; https://learn.microsoft.com/en-us/entra/identity-platform/publisher-verification-overview ; https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow |
| M5 | Registering an app needs an Entra tenant. That registration is free, and that a personal account with no directory can't register, are both **UNVERIFIED**. The quickstart lists an Azure account and a tenant as prerequisites. For `localhost` redirect URIs the port is ignored when matching. `127.0.0.1` needs a manifest edit, and `[::1]` isn't supported. | Partly | https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app ; https://learn.microsoft.com/en-us/entra/identity-platform/reply-url |
| M6 | Each refresh returns a new refresh token. Old ones are not revoked, and the default lifetime is 90 days. | Confirmed | https://learn.microsoft.com/en-us/entra/identity-platform/refresh-tokens |
