# What to build, from the parity design

Written 27 November 2026. The primary input is
[designs/heron-parity.md](designs/heron-parity.md) (reviewed through stage 9,
still a draft waiting for the owner). The facts it uses are in
[designs/research/heron-parity-competitors.md](designs/research/heron-parity-competitors.md).
Suggestion cards and interactive onboarding are a separate design,
[designs/heron-proactive-onboarding.md](designs/heron-proactive-onboarding.md).
The v1.0 qualification on 17–18 November is
[../qualification/reports/HERON-V1-RELEASE-QUALIFICATION.md](../qualification/reports/HERON-V1-RELEASE-QUALIFICATION.md).
Its verdict was **not ready**.

Nothing in the parity design is built. Approving that doc decides the first
group of reversals (recording audio, and a native iPhone app as a later
phase). Later phases each need their own short design before any code.

## Phase 1, once the owner approves the doc

1. Named agents. Several agents, each with a name, instructions, tools,
   permission scope and memory scope. Called by name in chat, and later by
   voice and from channels. An agent's own rules may be never or ask, never
   allow. Allow rules stay global.
2. Ask rules. Per-action "always ask" on the existing rule matcher.
3. Live voice. A button or a hotkey, not a wake word. Audio stays on the
   device and is not written to disk. Voice does not approve anything.
   The default model is the one the owner already uses.

## Later, each in its own delta

Messaging channels beyond Telegram, meetings, documents and slides, outbound
calls, a mobile app, and checkout that stops before payment. Cloud pieces
(a relay, a hosted voice agent, a meeting bot) stay off until the owner sets
them up, and none of them runs Heron's tools.

## Already fixed, or not this change

* Test runs no longer post desktop notifications through Script Editor.
  `App::notify` uses a configured command, the attached Mac app, or the
  Inbox. It does not call `osascript`. The older patch on
  `local-sync/claude/debug-running-heron-add995` targeted the previous
  function and does not apply.
* A `sandbox-exec` found earlier on `PATH` must not replace
  `/usr/bin/sandbox-exec`. That fix is its own pull request, with the test
  that stopped mutating the process-wide `PATH`.

## Still blocked on the owner

From the qualification, not from a missing screen:

* M-1. In Ask mode, text in a workspace file could steer a read of a
  credential and a `web_fetch` of that token with no approval. The
  qualification leaves the rule change to the owner.
* Whether phone turns stay in the desktop's permission mode (C35-8).
* Whether calendar titles, unconfirmed memories, and proactive prompts taint
  the conversation.
* Whether MCP callers count as outside content.
* `rusqlite` 0.32 is still the bundled SQLite. The qualification names
  RUSTSEC-2026-0459 and a move to 0.41. That upgrade is its own change.
* Live Telegram and OAuth tests need accounts this run does not have.
* A real Mac or Windows window, signing, and installer drills.

Do not start named agents, voice, or a new channel until those decisions
are made. A command palette (Ctrl+K) is separate and does not wait on them.
